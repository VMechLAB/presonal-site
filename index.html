About

I work across electronics, embedded programming, robotics, Python and CAD. Most of what's on this site was built from scratch — usually wrong the first time — and documented as I went rather than written up afterward to look tidy.

I care more about understanding why something works than getting it to work once and moving on. That means a lot of my "finished" projects still have loose ends, and I'd rather show that than hide it.

Where this is going

Long-term, I want a quiet life somewhere in nature, still building weird technical stuff — not a conventional office career.

How I got here

Electronics first, then robotics and embedded systems, then software to tie it together. Still mostly self-taught, still figuring out the gaps.

How I build

Build first

I learn fastest when I can actually build and test something, not just read about it.

Understand the system

I don't want something to simply work. I want to understand why it works.

Iterate

First versions are allowed to be rough. The goal is to keep improving them.

Document it

Projects should leave behind useful code, documentation and lessons — not just a working demo.
